# Стратегия репозитория — сокрытие ядра

## Цель

Участники команды работают только с оболочкой «База» и не имеют доступа к исходникам upstream.

## Варианты

### A. Отдельный репозиторий (рекомендуется)

- Репозиторий `baza` — содержит только penpot_for_base (docker, baza-api, assets)
- Upstream — git submodule в приватной ветке или образы из приватного registry
- Команда клонирует `baza`, не видит submodule (или он пустой для них)

### B. Монорепо с фильтром

- `baza/` — корень репозитория
- `baza/core/` — ограниченный доступ (только владелец)
- Права в Git: `.gitattributes` или отдельный репо для core

### C. Только оболочка

- В репо: baza-api, docker, assets, документация
- Образы ядра — собираются в CI, пушатся в приватный registry
- Команда не видит Dockerfile ядра, только docker-compose с образами

## CI/CD

- Переменные `BAZA_*` в пайплайне
- Сборка baza-api, образов (если форк)
- Публикация в registry с нейтральными именами: `baza-frontend`, `baza-backend`

## Ключевой принцип

Участники команды работают только с **baza-api** и документацией OpenAPI. Доступ к исходникам ядра — только у владельца проекта.
